# コードレビュー

## 対象
- ec-webapp

## レビューの観点
- ディレクトリ・ファイル構成
- 命名規則
- 設計・処理の分割方法
- コーディングスタイル・可読性
- エラーハンドリング
- セキュリティ対策
- 処理効率
- テストのしやすさ

## 出力形式
改善点がある場合は、観点ごとに「課題・改善方法・改善理由」を具体的に説明し、下記の表形式で出力してください。

- 1つの観点に複数の課題がある場合は、行を分けてすべて記載してください。
- 各観点内では重要度が高い順に並べてください。
- 課題には該当ファイル（可能であればファイル名・行番号）を明記してください。

| 観点 | 重要度 | 対象ファイル | 課題 | 改善方法 | 改善理由 |
|------|--------|--------------|------|----------|----------|
|      | 高/中/低 |              |      |          |          |

改善点がない観点については、表の外にその旨を明記してください。

## 総評
最後に、全体を通じた総評（特に優先して対応すべき課題）を3〜5行程度で記載してください。
